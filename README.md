# 오늘의 트렌드 레이더

MZ세대 소비문화·콘텐츠·마케팅 트렌드를 **최상류 / 상류 / 중류** 세 단계로 나눠 기록하는 일일 리포트입니다.
아직 대중화되지 않았지만 앞으로 한국 시장에 영향을 줄 가능성이 있는 신호를 먼저 잡는 것이 목적입니다.

🔗 **[리포트 보기 → jenzeae-c.github.io/trend-radar](https://jenzeae-c.github.io/trend-radar/)**

---

## 단계 기준

| 단계 | 정의 |
|---|---|
| **최상류** | 아직 국내에서 유행하지 않았거나 일부 얼리어답터만 감지하는 단계. 해외 SNS·커뮤니티·크리에이터·신생 서비스에서 먼저 발생한 신호 |
| **상류** | 국내 SNS·커뮤니티·일부 브랜드에 유입되기 시작했지만 아직 대중적 현상은 아닌 단계 |
| **중류** | 여러 브랜드·플랫폼·미디어가 이미 움직여 하나의 흐름으로 확인되는 단계. 단, 정점을 지난 트렌드는 제외 |

## 카테고리

- **종합 트렌드** — 소비 · 콘텐츠 · 마케팅
- **K-POP** — 아티스트 · 팬덤 · 공연

각 카테고리마다 세 단계를 모두 채워 회차당 6개를 싣습니다.

## 선정 규칙

- **최근 2주 이내**에 새로 관측된 변화만 후보로 올립니다. 트렌드 자체가 그 이전에 시작됐더라도, 이 기간 안에 확산·브랜드 진입·서비스 출시·한국 유입 같은 새 움직임이 확인돼야 합니다.
- 서로 **독립적인 신호 2개 이상**이 확인된 것만 싣습니다.
- 최초 발원지가 불확실하면 단정하지 않고 "현재 확인되는 초기 확산 지점은 ○○"로 적습니다.
- 근거가 약한 대목에는 회색 표시를 달아 **사실과 해석을 구분**합니다.
- 이전 회차와 같은 주제는 확산 단계가 실제로 이동했다는 새 근거 없이 다시 싣지 않습니다.

각 트렌드는 `단계 판정 근거 → 시작 신호가 보이는 곳 → 왜 지금 한국에서 주목해야 하는지 → 확산 경로 → 활용 아이디어 2개(브랜드용·콘텐츠용)` 순서로 씁니다.

## 파일 구성

| 파일 | 용도 |
|---|---|
| `index.html` | 웹 배포용. Pretendard를 jsDelivr 동적 서브셋으로 불러와 가볍습니다 (약 69KB) |
| `standalone.html` | 완전 자립형. 폰트를 파일 안에 내장해 인터넷 없이도 동일하게 보입니다 (약 2.7MB) |

두 파일의 내용은 같습니다. 웹에서 공유할 때는 `index.html`, 파일 하나만 주고받을 때는 `standalone.html`을 쓰세요.

## 새 회차 추가하기

`index.html` 안에서 두 군데만 손보면 아카이브·목차·단계 필터가 자동으로 따라옵니다.

**1) 본문에 회차 추가** — `<main>` 안 맨 앞에 새 `article`을 넣습니다.

```html
<article class="report" data-date="2026-08-14">
  <div class="lede">…</div>

  <section class="cat" data-cat="general">
    <section class="trend" data-stage="up" id="g1" data-title="트렌드 이름">…</section>
    <!-- data-stage: up(최상류) / mid(상류) / low(중류) -->
  </section>

  <section class="cat" data-cat="kpop" hidden>…</section>
</article>
```

**2) 목록에 등록** — 파일 하단 `<script>`의 `REPORTS` 배열 맨 앞에 추가합니다.

```js
var REPORTS = [
  { date: "2026-08-14", label: "8월 14일 리포트", note: "한 줄 요약" },
  …
];
```

`data-date`와 `REPORTS`의 `date`가 정확히 일치해야 연결됩니다.
